# 迭代与测试计划

## 1. 当前版本

V0.2：已实现知识资产→样本审核→批量问答→规则/模型评分→人工复核→实验对比→回归再执行的核心功能链路。完整真实模型验收需要独立可用的Embedding配置，未完成的验证不会标为通过。

| 模块 | 当前实现 |
| --- | --- |
| 资产 | Markdown/TXT上传、JSON导入、草稿编辑、不可变发布、版本复制 |
| 知识处理 | 字符切分、来源偏移与标题信息、预览、异步索引、完整性检查后发布 |
| 样本审核 | 逐条人工审核历史、操作人、理由、内容哈希；修改后审核失效 |
| 模型 | 通义/DeepSeek兼容生成；独立Embedding与Judge连接器；提示词v1/v2 |
| 问答 | LangGraph、来源引用、拒答、耗时、Token、问答配置与历史 |
| 执行 | Celery样本任务、并发1～5、调用超时、有限重试、尝试历史、租约和恢复调度 |
| 评分 | 规则检查、独立模型结构化评分、证据校验、独立评分失败及重试 |
| 人工复核 | 追加记录与归因，保留原始评分，整体判定优先人工结果 |
| 报告 | 分维度指标与有效分母、证据召回、拒答、耗时、Token及类型分组 |
| 对比导出 | 双实验指标和逐条回答、内容变更识别、失败变化分类、JSON/CSV |
| 回归 | 人工确认失败后加入草稿集，保存来源与修复条件，再审核发布运行 |
| 权限 | 管理员全部权限；测试角色编辑执行；复核角色审核复核；其余登录用户只读 |

## 4. 已知边界

1. 文档与样本仍使用版本化JSON聚合存储，索引任务、审核、执行尝试、问答历史、回归来源已独立建表。
2. 当前按字符切分，未实现语义标题切分；模型的证据充分性依赖提示词与无检索结果规则，尚无独立充分性分类器。
3. 人工复核当前修正整体通过/失败，各维度报告展示原始自动评分并明确口径；未提供每维度人工覆盖。
4. 生成和评分均可配置模型，供应商返回的模型标识尚未逐次独立保存；配置已冻结模型及端点。
5. macOS使用threads池兼容本机Celery；该池不支持任务硬超时，依靠网络调用超时、有限重试和租约恢复。生产使用Linux prefork池。
6. 恢复依赖Celery Beat或手动recover_jobs；租约为15分钟，恢复不是瞬时完成。数据库轮询恢复保证可重投，不承诺消息恰好一次交付。
7. 分角色API权限已实现，尚未提供组织/项目隔离与完整操作审计。
8. 尚未完成高并发容量压测和生产部署评审。

## 5. 验收方法

按01需求规格AC-01到AC-07逐项执行。先执行scripts/check.sh，再执行scripts/run_e2e.py。真实服务检查使用scripts/check_mysql.py（事务回滚）和scripts/check_queue.py（明确离线生成的真实队列检查）。真实模型实验必须使用已发布live索引、人工审核数据集和model评分模式；报告必须标明配置与有效分母。
