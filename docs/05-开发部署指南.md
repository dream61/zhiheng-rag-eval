# 开发部署指南

## 1. 环境与虚拟环境

推荐Python3.12、Node20、Docker Compose。用VS Code打开zhiheng-rag-eval工程目录，默认解释器已指向.venv/bin/python。若此前选过其他解释器，执行“Python: Select Interpreter”选择该路径。不要用sudo pip或全局pip安装本项目包。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.lock.txt
npm ci --prefix frontend
cp .env.example .env
```

前端依赖由npm安装到frontend/node_modules，与Python虚拟环境分开。敏感配置只填本地.env，已被Git忽略。

## 2. 标准开发模式：MySQL与Celery

在工程根目录执行：

```bash
docker compose --env-file .env -f infra/compose.yaml up -d
source .venv/bin/activate
cd backend
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8000
```

另开终端，从工程根目录执行：

```bash
source .venv/bin/activate
cd backend
celery -A config worker -l info --pool=solo
```

再开终端执行前端：

```bash
npm run dev --prefix frontend
```

访问http://127.0.0.1:5173，使用创建的本地用户登录。Admin在http://127.0.0.1:8000/admin/，仅用于用户管理和业务只读查看。启动前确认3306、6379、6333、8000、5173未被其他项目占用。

## 3. 无基础服务的离线功能验证

在运行后端的终端设置以下环境变量，再执行迁移、创建用户和启动命令：

```bash
export DB_ENGINE=sqlite
export CELERY_TASK_ALWAYS_EAGER=1
export RAG_BACKEND=mock
```

此模式使用SQLite、同步执行任务、字符匹配与原文摘录，方便验证页面和业务流程；不会验证MySQL、Redis、Celery调度、Qdrant或真实模型质量。标准模式仍以MySQL为默认数据库。

## 4. 操作步骤

1. 导入演示草稿，知识资产页面检查文档并发布。
2. 数据集页面打开样本JSON，人工核对参考答案、证据与拒答标签。
3. 核对后手工将approved设为true，保存并发布。演示资料不等于50条已审核验收集。
4. 问答调试选择知识库和执行模式，检查回答及证据。
5. 评测实验选择数据集，分别提交Top K为3和5的实验。
6. 点击刷新查看执行状态，再查看报告与结果。
7. 对规则通过且待判定的样本进行语义复核，记录理由和归因。

当前尚无双实验对比页面和回归集操作入口，见迭代计划。

## 5. 真实模型接入

.env中设置LLM_API_KEY、LLM_BASE_URL、LLM_MODEL、EMBEDDING_MODEL及QDRANT_URL；页面选择live。当前生成和Embedding共用兼容端点，默认面向通义服务。若接入不提供Embedding的供应商，需先实现独立Embedding配置，不能仅替换生成地址后直接运行。

真实模式首次问答会创建索引，当前请串行执行，并控制资料量。密钥不能放入JSON资产、前端代码或截图。

## 6. 验证命令

```bash
source .venv/bin/activate
cd backend
DB_ENGINE=sqlite CELERY_TASK_ALWAYS_EAGER=1 python manage.py check
DB_ENGINE=sqlite CELERY_TASK_ALWAYS_EAGER=1 pytest -q
```

在工程根目录执行：

```bash
npm run build --prefix frontend
```

需要执行界面测试时先启动前端，再安装浏览器并运行：

```bash
cd frontend
npx playwright install chromium
npm run test:e2e
```

## 7. 停止与数据

终端Ctrl+C停止开发进程；docker compose -f infra/compose.yaml stop停止基础服务。开发卷持久化资料，停止不会清理。生产部署、备份恢复和外网访问配置尚未交付。
